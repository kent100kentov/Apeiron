# Движок Apeiron: контракт первой реализации

Новый код, без зависимости от другого проекта. Исходная спецификация: MASTER-REFERENCE.md.
Предлагаемые интерфейсы ниже ещё не реализованы.

## Состояние

World { id, parentPlaceId, seed, rulesVersion, layoutRevision, places, entities, clock }
Place { id, worldId, position, orientation, ports, state, resources, childWorldId }
Entity { id, location, owner, kind, abilities, inventory, condition }
Character extends Entity { goal, knowledge, relationships }
Episode { id, placeId, entry, participants, objective, budget, support, revision, status }
Result { id, causeId, changes, applied }

Идентичность отдельно от координат. Все количественные изменения имеют источник и получателя/затрату.

## Интерфейсы

createWorld(seed, rules, theme)
legalActions(state, actorId)
preview(state, command, knowledge)
apply(state, command) -> { state, events }
enterWorld(state, actorId, placeId, port)
transform(state, worldId, permutation)
resolveEpisode(state, episodeId, result)
snapshot(state)
restore(snapshot, bundle)
replay(initial, commands, bundle)

apply не меняет входной объект при ошибке. Команда содержит ожидаемую ревизию и идентификатор. Известный повтор возвращает прежний результат, не исполняется снова.
Пакет правил определяет условия и цену до выполнения. Не смешивать чтение preview с расходом игровых ресурсов.
Случайность привязана к seed, номеру команды и именованному потоку; частота кадров не влияет на исход.

## Перестановка

Проверить разрешённость → построить новую таблицу положений → проверить ограничения → применить атомарно → увеличить ревизию.
Принадлежность дочерних миров и содержимого месту не меняется.
Если целевой вход/выход после изменения недоступен, старый прогноз требует пересчёта.

## Эпизод

Подготовка: зафиксировать участников, вход, поддержку, цель, бюджет и выходы.
Действие: валидировать → списать цену → применить результат → проверить локальное завершение.
Разрешение: один resultId и атомарное изменение родителя.
Нельзя сбрасывать бюджет/потери повторным входом.
Базовая сцена не требует разрешить бесконечное число дочерних сцен.

## Запись

В первой реализации выбрать собственный формат после определения команд. Начать с проверяемого текстового представления, затем измерить и добавить бинарное кодирование.
Совместимость важнее обещания произвольного размера. Нужны версии, контроль целостности и явный отказ от неизвестного пакета.
Снимки ускоряют продолжение; журнал сохраняет причины и воспроизведение.

## Тесты

Инварианты владения, количества и идентичности; обращение геометрической перестановки; воспроизведение; отказ устаревшей команды; однократное завершение; пауза/выход/возврат; отсутствие бесконечной обязательной рекурсии.
Эти тесты предстоит написать вместе с новой реализацией.
